# TraceForce 两分钟演示视频脚本

目标成片时长：**1 分 50 秒至 1 分 55 秒**。录制时可以完整运行任务，后期将模型思考、文件编写和重复工具调用加速或跳切；不得伪造命令输出。

## 录制前准备（不进入成片）

1. 关闭通知、聊天窗口和可能显示个人信息的软件；终端使用大字号，建议 18–22 px。
2. API key 已通过本地环境文件加载，但视频中不运行 `env`、`printenv` 等命令，也不展示配置文件。
3. 浏览器提前打开 README，终端提前进入仓库根目录。
4. 运行任务三的 `setup.sh`，确认 workspace 为空；正式录制时可以再次运行，以证明可复现。
5. 完整录制一次 Agent 执行过程，另录 README、初始 verifier、最终 verifier 和浏览器成品，最后剪辑成片。
6. 成片只使用真实运行产生的画面；可加速和删减等待，不修改测试结果。

## 完整时间轴与口播

### 00:00–00:12　项目定位

**画面**

- 打开 GitHub README 顶部，缓慢滚动到项目简介和功能列表。
- 不展示任何包含 API key 的终端内容。

**口播**

> 大家好，这是我独立设计并实现的编程智能体 TraceForce。它能在指定工作区内自主读取和修改文件、执行命令、处理错误并验证结果，目标是完成真实的软件工程任务，而不只是生成代码片段。

### 00:12–00:35　实现结构与特色

**画面**

- 滚动到 README 的架构图。
- 依次用鼠标指出 LLM、Runtime、Tools、TUI 和 Workspace。

**口播**

> 项目没有使用任何 Agent 框架。模型适配、流式 tool-call 解析、对话与上下文管理、Agent 循环、终止条件以及本地工具执行都由我实现。整体分为模型协议层、运行时和产品层；工具被限制在 workspace 内，写文件和执行命令前需要权限确认，工具错误也会返回模型继续修复。TUI 只是运行时事件的可视化消费者，不包含另一套 Agent 逻辑。

### 00:35–00:52　说明评测任务

**画面**

- 滚动到 README 的 Evals 表格。
- 画面依次停留在三个任务名称上。

**口播**

> 我准备了三类独立评测。第一个是 tqdm 的真实回归：非零起始值被错误传给进度条构造函数。第二个是 Sanic 的真实问题：Blueprint 响应中间件的注册顺序与框架语义相反。第三个从空目录创建一个无外部依赖的 DevBoard 静态网页。下面完整展示第三个任务。

### 00:52–01:01　证明初始状态失败

**画面**

- 切换到仓库根目录终端，依次执行：

```bash
evals/tasks/03-devboard-greenfield/setup.sh
evals/tasks/03-devboard-greenfield/verify.sh
```

- 保留 verifier 的真实失败信息：缺少 `index.html`。

**口播**

> 首先由 setup 恢复一个空 workspace。独立 verifier 此时失败，证明交付物尚不存在。

### 01:01–01:32　Agent 完成真实任务

**画面**

- 在 workspace 中启动 TUI：

```bash
cd evals/workspaces/03-devboard-greenfield
traceforce --tui
```

- 粘贴任务三要求。
- 保留以下关键镜头，其余过程加速 4–8 倍或跳切：
  1. Agent 查看空 workspace；
  2. Agent 说明实现计划；
  3. `write` 权限弹窗，手动点击 Allow；
  4. 工具卡片显示写入 `index.html`、`styles.css`、`script.js`；
  5. Agent 执行本地检查并根据结果继续工作；
  6. Agent 给出中文完成总结。

**口播**

> 我把自然语言需求直接交给 TraceForce。Agent 先检查工作区，再规划文件结构；写入操作会触发权限确认。得到授权后，它创建页面、响应式样式和交互脚本，并通过本地命令检查实现。这里对等待过程进行了加速，但保留了真实的工具调用和执行结果。

### 01:32–01:47　独立验证与浏览器结果

**画面**

- 退出 TUI，回到仓库根目录运行：


- 清楚展示：

- 切换到浏览器中的最终页面，点击一次筛选或详情交互，再快速缩窄窗口展示响应式布局。

**口播**

> 完成后，再由 Agent 之外的独立 verifier 检查静态文件、本地资源、响应式规则和交互脚本，验证通过。最终页面可以直接运行，交互和窄屏布局也正常工作。

### 01:47–01:55　结束总结

**画面**

- 回到 README 顶部或最终网页全景。

**口播**

> TraceForce 展示的是从理解需求、调用工具、修改文件到独立验证的完整工程闭环。以上就是我的演示，谢谢。

## 任务输入文本

录制时直接粘贴下面这段，不需要让 Agent 读取 workspace 外的 `task.md`：

```text
请从当前空 workspace 开始，创建一个完整、有打磨感的 DevBoard 前端，用于帮助开发者快速查看 repository 健康状况。只使用原生 HTML、CSS 和 JavaScript，不使用框架、构建工具、包管理器、CDN 或远程资源。交付 index.html、styles.css 和 script.js；页面需要有清晰的 dashboard 标题、整体健康状态、实用状态信息、桌面与窄屏响应式布局，以及至少一个有意义的交互。完成后请运行本地检查验证文件引用、响应式规则和交互实现，并总结验证结果。
```

## 建议保留和删除的画面

**必须保留**

- README 中的项目定位和架构图；
- 初始 verifier 失败；
- 至少一次真实权限确认；
- read/write/bash 等真实工具卡片；
- 最终独立 verifier 通过；
- 浏览器中的交互和响应式结果。

**应当删除或加速**

- 模型长时间等待；
- 重复读取文件；
- 大段代码逐字滚动；
- 与演示结论无关的终端输出；
- 任何失败后已经重新录制成功、但容易让观众误解的旧会话画面。

## 录制失败备用方案

- 如果模型调用失败，停止录制并重新运行，不要在成片中假装成功。
- 如果 Agent 生成内容不满足 verifier，保留首次失败作为开发证据也可以，但主演示应继续让 Agent修复，直到真实通过。
- 如果 TUI 动画影响可读性，降低后期加速倍数，不要通过删除工具结果来制造完成假象。
- 如果浏览器预览来不及启动，可在录制前使用 `python3 -m http.server 8000`，但必须从任务 workspace 启动，且不要把持续运行的服务交给 Agent。

## 成片导出检查

- 时长不超过 2 分钟；
- MP4 格式，小于 200 MB；
- API key、环境变量、个人通知和隐私路径未出现在画面中；
- 字体在 1080p 播放时清晰可读；
- 所有 PASS、页面和工具调用均来自同一次真实任务结果；
- 口播没有声称使用了尚未实现或尚未验证的能力。
