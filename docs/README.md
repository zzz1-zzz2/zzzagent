# TraceForce 文档

这里放适合代码审查、开发维护和项目答辩的补充说明。根目录 [README.md](../README.md) 是使用入口；本目录不复制源码注释，而是解释模块之间的边界、验证方法和演示流程。

## 推荐阅读顺序

| 读者 | 入口 |
| --- | --- |
| 第一次了解项目 | [根 README](../README.md) → [架构说明](architecture.md) |
| 想本地运行和开发 | [开发指南](development.md) |
| 想复现工程任务 | [评测指南](evaluation.md) → [`evals/README.md`](../evals/README.md) |
| 准备推免答辩或现场演示 | [演示脚本](demo.md) |
| 查看未完成能力 | [路线图](../ROADMAP.md) |

## 文档原则

- **实现与证据分开**：packages/ 说明实现了什么，evals/ 说明如何独立验证；
- **明确状态**：已实现、已测试、待完成和需要人工验收的内容分别写清楚；
- **不保存秘密**：示例只使用占位模型名，API key 只来自环境变量或未入库配置文件；
- **不夸大安全边界**：内置 bash 是非交互执行工具，不是操作系统级沙箱；
- **以代码为准**：当文档和实现不一致时，应先修正文档或明确记录差异。

## 目录边界

```text
packages/  产品、运行时和模型边界的实现
 evals/    可复现任务、setup、独立 verifier 和脱敏证据约定
docs/      面向读者的架构、开发、评测和演示说明
```
